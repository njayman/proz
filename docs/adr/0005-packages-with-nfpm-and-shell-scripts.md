# Packages are built with nfpm and shell scripts, not GoReleaser

The installers spec (#66) planned for GoReleaser OSS to drive packaging. We build the Linux packages with nfpm (GoReleaser's own packager) called from `scripts/package-linux.sh`, and check them with `scripts/check-linux-package.sh`, both run from plain GitHub Actions jobs next to the existing release workflow. The desktop build needs cgo, so each OS and architecture builds on its own native runner, and GoReleaser OSS cannot merge those per-runner builds into one release (that is a Pro feature); we would have run GoReleaser once per runner anyway and still needed our own glue to attach the artifacts. Two short scripts keep one release system instead of two, run the same way on a laptop and in CI, and need no Go dependency. If the release grows past what the scripts handle comfortably (many formats, signing and store manifests in one place), this is reopened with GoReleaser Pro's split and merge as the alternative.
