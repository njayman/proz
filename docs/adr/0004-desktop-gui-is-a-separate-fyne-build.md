# The desktop GUI is a separate Fyne build

The launcher is written in Fyne and sits behind a `gui` build tag, separate from `tray`. Desktop installers ship the `gui,tray` build by default; the plain cgo-free build is still published for servers, the Pi, tarballs and `go install`. `proz gui` runs as its own short-lived process that calls `core` directly, and the tray starts it rather than hosting the window. The phone app is a separate HTML UI on `proz serve`; the two share data and the agent contract, not UI code. We chose this over one shared HTML UI (Wails v3) because the surfaces do different jobs (the desktop launches local programs, the phone cannot), Wails v3 is still beta and would replace a working tray, and over one always-GUI binary because Fyne needs cgo and OpenGL, which would stop proz starting on headless machines. Screen reader support (`-tags accessibility`) is always on in desktop builds. If the GUI spike misses its criteria (opens under 1s, works on Sway, Orca reads it), this is reopened with Wails v3 as the alternative.
